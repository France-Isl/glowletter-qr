# GlowLetter: выдача VIP-доступа

Административный раздел доступен только подтверждённому аккаунту владельца `ggooglov9@gmail.com`. Пароли пользователей, UUID и доступ к панели Supabase для этой работы не нужны.

## Как пользователь находит свой ID

1. Пользователь входит в GlowLetter через подтверждённый e-mail или доступный социальный способ.
2. Открывает «Настройки» → «Аккаунт и синхронизация».
3. В блоке «ID аккаунта» нажимает «Скопировать».
4. Передаёт полный ID вида `GL-XXXX-XXXX-XXXX-XXXX-XXXX-XXXX-XXXX-XXXX` владельцу.

ID поддержки помогает найти аккаунт, но не является паролем и сам по себе не даёт доступа к данным пользователя. В админ-панели по нему видны только ID, дата создания и состояние доступа.

## Как выдать VIP на нужное число дней

1. Войдите в GlowLetter именно через `ggooglov9@gmail.com`.
2. Откройте «Настройки» → «Панель администратора».
3. Вставьте ID пользователя и нажмите «Найти».
4. Проверьте найденный ID и текущий статус.
5. В поле «Срок VIP» укажите целое число от 1 до 365.
6. Нажмите «Выдать VIP».

Срок отсчитывается от момента выдачи по серверному времени. Новая выдача заменяет предыдущую дату окончания: она не складывает дни с уже действующим сроком. У пользователя доступ появится автоматически, обычно в течение минуты, без повторного входа.

## Как отозвать VIP

Найдите аккаунт тем же способом и нажмите «Отозвать VIP». Постоянный доступ владельца этой кнопкой не снимается.

## Что видит пользователь

В настройках показываются статус и точный остаток времени: дни, часы и минуты, а также дата окончания. Проверка обновляется автоматически, пока приложение открыто, и повторяется при возвращении в приложение или появлении интернета.

## Публичная подписка

Для покупателей остаётся один понятный тариф: ежемесячная подписка за базовые 21,99 € за календарный месяц. Фактическую локальную цену и валюту перед оплатой показывает Google Play или App Store. Магазинная подписка продлевается автоматически до отмены пользователем.

Ручной VIP из панели администратора не проводит оплату, не продлевается автоматически и предназначен для друзей, тестировщиков, поддержки и специальных случаев. Можно выдать ровно от 1 до 365 дней, в том числе 30 дней.

## Приватное аудио в персональной ссылке

Выбранный аудиофайл обычно остаётся только на устройстве. Если пользователь при создании персональной ссылки явно выбирает приложить аудио, приложение приватно загружает его копию на сервер максимум на 12 часов. Получатель с секретной ссылкой может слушать файл только в этот период. После окончания срока доступ блокируется и файл удаляется. Если техническая очистка завершится чуть позже, воспроизведение всё равно уже недоступно. Исходное имя файла на сервере не хранится. Пользователь сам отвечает за права на аудио и его содержание. Обычная функция «Поделиться приложением» и QR‑код аудио не передают.

## История «Моменты»

«Моменты» включаются только по выбору вошедшего пользователя. В Supabase сохраняются профили важных людей, важные даты и настройки напоминаний, явно сохранённые окончательные письма и метаданные непрозрачных QR-ссылок. Черновой prompt, исходная мысль и промежуточные инструкции генератору не сохраняются.

Таблицы `glowletter_people`, `glowletter_moments`, `glowletter_letters` и `glowletter_qr_links` работают с RLS: пользователь видит только строки своего `auth.uid()`. Не выдавайте `anon` прямой `SELECT` на эти таблицы и никогда не помещайте `SUPABASE_SERVICE_ROLE_KEY` в PWA, APK, AAB, репозиторий или сообщение поддержки.

Публичный QR содержит случайный `public_id`. Текст через него выдаёт только Edge Function `resolve-letter`, вызывающая `glowletter_resolve_qr_link` с серверными правами. До `unlock_at` ответ содержит состояние и время открытия без текста; отозванная или истёкшая ссылка также не раскрывает письмо. Разрешённая ссылка после открытия отдаёт только имена для показа, заголовок, язык и текст.

Перед публикацией обновления:

1. Примените миграцию Moments к тому же Supabase-проекту, который указан в `config.js`.
2. Разверните Edge Function `resolve-letter` и оставьте `verify_jwt = false`: получатель QR может не иметь аккаунта, а сама функция проверяет origin и UUID и использует серверный RPC.
3. Убедитесь, что в секретах функции доступны стандартные `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`; ключ не копируется в клиент.
4. Проверьте четыре состояния ссылки: `locked`, `ready`, `revoked` и `expired`. В первых, третьем и четвёртом состояниях текст до клиента доходить не должен.
5. Удалите тестовый аккаунт и убедитесь, что связанные люди, даты, письма и QR-метаданные исчезли каскадно, а прежняя публичная ссылка перестала открываться.

Напоминания показываются внутри приложения. Кнопка календаря создаёт `.ics`-файл по действию пользователя; приложение не получает доступ к содержимому календаря. После импорта уведомления настраиваются в календаре телефона.

Обновление намеренно не содержит логотип магазина или флориста, полей Instagram и истории заказов. Не добавляйте эти сведения в профили людей, письма или QR-метаданные.

## Вход и подтверждение e-mail

В интерфейсе есть вход по паролю, регистрация и подтверждение шестизначным кодом. Адрес незавершённой регистрации хранится только в `sessionStorage`; сам код приложение не сохраняет. Повторная отправка становится доступна после минутного таймера.

Для production один раз проверьте в Supabase Dashboard → Authentication:

1. Разрешена регистрация по e-mail и обязательно подтверждение адреса (`Confirm email` включён, mailer autoconfirm выключен).
2. Длина OTP — 6 цифр, срок действия ограничен. Не увеличивайте его без необходимости.
3. Указаны production Site URL и разрешённые redirect URL для GitHub Pages и мобильного callback.
4. Настроен production SMTP и понятные темы/тексты писем на русском, английском и французском. SMTP-пароль хранится только в Supabase Secrets/Dashboard.
5. Выполнены тесты: новая регистрация без подтверждения не получает сессию; правильный код создаёт сессию; неверный/просроченный код отклоняется; повторная отправка ограничена; существующий пользователь входит паролем.

Никогда не просите пользователя прислать пароль или код. Если письмо не пришло, проверьте SMTP-логи, папку «Спам», лимиты отправки и точность адреса. Не отключайте подтверждение e-mail как способ устранения проблемы доставки.

## Безопасность

- Никому не передавайте пароль Google, доступ к Supabase или ключи проекта.
- Всегда сверяйте полный ID перед выдачей или отзывом VIP.
- Не публикуйте закрытую owner-сборку и приватную ссылку в открытом доступе.
- Все административные изменения записываются в защищённый журнал.
- Журнал выдачи и отзыва VIP автоматически удаляется через шесть месяцев.

## Встроенная поддержка и уведомления на Gmail

Пользователь открывает «Настройки» → «Поддержка», входит в аккаунт, выбирает тему и описывает проблему. Подтверждённый email аккаунта и ID поддержки прикладываются сервером автоматически — вводить или копировать ID в форму не нужно. Обращение сначала сохраняется в закрытом разделе Supabase. Другие пользователи не могут читать или изменять эти записи. На один аккаунт разрешено не более 3 обращений в час и 10 в сутки; обращения автоматически удаляются через шесть месяцев.

Чтобы каждое новое обращение также приходило на `ggooglov9@gmail.com`, один раз подключите бесплатный почтовый API Resend:

1. Создайте аккаунт Resend и подтвердите домен отправителя либо разрешённый тестовый адрес.
2. В Supabase Dashboard откройте проект GlowLetter → Edge Functions → Secrets.
3. Добавьте `RESEND_API_KEY` — ключ Resend. Вводите его только в Supabase Dashboard, не отправляйте в чат и не сохраняйте в GitHub.
4. Добавьте `SUPPORT_FROM_EMAIL` — подтверждённый отправитель, например `GlowLetter Support <support@ваш-домен.fr>`.
5. При желании добавьте `SUPPORT_TO_EMAIL=ggooglov9@gmail.com`; если не добавлять, этот адрес уже используется сервером по умолчанию.
6. Отправьте тестовое обращение из своего аккаунта. После успешной доставки пользователь увидит подтверждение, а письмо придёт с темой `GlowLetter support` и будет содержать ID, категорию, платформу, версию и описание проблемы.

Если Resend ещё не подключён или временно недоступен, обращение не теряется: оно остаётся безопасно сохранённым в Supabase, а приложение честно сообщает, что email-уведомление ещё настраивается. Gmail-адрес сам по себе не умеет принимать автоматические запросы от приложения без такого серверного почтового ключа.

### Если обращение сохранилось, но письма на Gmail нет

1. В Supabase Dashboard откройте GlowLetter → Edge Functions → Secrets.
2. Проверьте наличие именно имён `RESEND_API_KEY` и `SUPPORT_FROM_EMAIL`. Значения никому не показывайте.
3. В Resend проверьте, что отправитель из `SUPPORT_FROM_EMAIL` разрешён. Для рабочего домена он должен быть подтверждён; тестовый отправитель Resend имеет ограничения по получателям.
4. Отправьте новое обращение из вошедшего аккаунта. Сообщение «Обращение отправлено в поддержку» означает, что Resend принял email. Сообщение о сохранении означает, что тикет записан, но email не был отправлен.
5. Если отправка принята, но письма нет, проверьте журнал Emails в Resend, а затем «Спам» и «Все письма» в Gmail.

## Вход через Apple ID и Facebook

Кнопки социальных провайдеров появляются автоматически только после их полноценного включения в Supabase. Это защищает пользователя от неработающих кнопок. Никогда не записывайте Client Secret, Apple `.p8` или Meta App Secret в GitHub, приложение или сообщение поддержки.

Общий callback для обоих провайдеров:

```text
https://xzzngrquomyiglktroqi.supabase.co/auth/v1/callback
```

### Apple ID

1. Нужен активный Apple Developer Program и App ID `com.franceisl.glowletternext` с возможностью Sign in with Apple.
2. В Apple Developer создайте Services ID для веб-входа и привяжите его к App ID.
3. Для Services ID укажите домен `xzzngrquomyiglktroqi.supabase.co` и callback выше.
4. Создайте Sign in with Apple key и сохраните `.p8` только в защищённом месте.
5. В Supabase Dashboard → Authentication → Sign In / Providers → Apple добавьте Services ID первым Client ID и созданный Apple client secret, затем включите провайдер.
6. Для OAuth-входа Apple client secret нужно обновлять не реже одного раза в шесть месяцев. Потерянный или раскрытый `.p8` немедленно отзывается в Apple Developer.

В интерфейсе функция называется «Продолжить с Apple». Это вход через Apple ID — тот же аккаунт, которым пользователь пользуется для iCloud и App Store; отдельного входа «через iTunes» нет.

### Facebook

1. В Meta for Developers создайте приложение и добавьте Facebook Login.
2. В Valid OAuth Redirect URIs добавьте callback выше без лишнего слеша.
3. Разрешите `public_profile` и `email`. Email обязателен для профиля GlowLetter и обращений в поддержку.
4. В Supabase Dashboard → Authentication → Sign In / Providers → Facebook добавьте Meta App ID и App Secret, затем включите провайдер.
5. Пока приложение Meta находится в Development mode, войти смогут только добавленные администраторы, разработчики и тестировщики. Перед публичным запуском переведите приложение в Live mode и выполните требования Meta.

После включения провайдера откройте GlowLetter заново: приложение читает актуальную конфигурацию Supabase и показывает соответствующую кнопку без хранения каких-либо секретов на устройстве.
